# Sales Performance Dashboard
**Project 1 - B.Tech 2nd Year Data Analytics (Retail and e-commerce)**
Python (cleaning) -> Oracle SQL (star schema and analysis) -> Power BI (dashboard)

## What this project answers
How are sales and profit trending, which products / regions / segments drive revenue, and does discounting help or hurt profit? Full problem statement and KPI definitions: `docs/01_problem_statement_and_KPIs.md`.

## Headline results
| KPI | Value |
|---|---|
| Total sales | Rs 83,017,884.76 |
| Total profit | Rs 13,369,626.22 (16.1% margin) |
| Orders / customers | 7,159 / 900 |
| Key finding | Discounts above 10% cut margin from 21.0% to 3.3% (11-20%) and **-5.5%** (21-30%); every loss-making line sits above 10% discount |

## How to run
```bash
pip install pandas numpy matplotlib
python src/01_generate_raw_data.py     # creates data/raw_sales.csv (skip if you use a real Kaggle CSV)
python src/02_clean_data.py            # cleaning, quarantine, star-schema CSVs, expected KPIs
python src/03_validate_sql_logic.py    # checks every SQL aggregate reconciles to the total
python src/04_insights_and_charts.py   # charts and ER diagram
```
**Oracle:** in SQL Developer run `sql/01_create_tables.sql`, then load the CSVs (SQL*Loader files in `sql/sqlldr/`, or SQL Developer's Import Data wizard, loading parents before the fact table), then `02_analysis_queries.sql` and `03_views.sql`.
**Power BI:** follow `powerbi/POWERBI_BUILD_GUIDE.md`.

## Data source
The included dataset is **synthetic** (generated by `src/01_generate_raw_data.py`) with realistic seasonality and deliberately injected errors so each cleaning rule can be demonstrated. To use a real Kaggle retail-sales CSV, map its columns to the 18 columns listed in `src/02_clean_data.py` and save it as `data/raw_sales.csv`; everything downstream runs unchanged.

## Data quality and reconciliation
12,865 raw rows -> 190 duplicates removed -> 140 rows quarantined -> **12,535 clean rows**. All SQL aggregates (regions, segments, categories, months, states, discount bands) sum to the total with **0.0000%** difference. Details: `docs/02_data_quality_report.md`.

## Test cases covered
Null/duplicate rows, negative amounts, date-format errors (4 formats + impossible dates), region casing, extreme outliers - each handled by a numbered rule (R1-R11).
